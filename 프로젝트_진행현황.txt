여행 준비 도우미 프로젝트 진행 현황
작성일: 2026-11-09

1. 저장 위치
- 앱과 광고센터 소스: https://github.com/kdju1212/trip_cal
- 작업 브랜치: codex/travel-prep-v1 (기본 브랜치에 합쳐졌다는 뜻은 아님)
- 광고·계정 등 서비스 데이터: Supabase
- 광고센터: https://trip-cal-ad-center.djkim0509.chatgpt.site
  현재 광고센터는 소유자만 접속할 수 있는 비공개 상태다.

2. 현재 상태
- 앱은 여행 기간, 예상 경비, 남은 예산, 체크리스트, 여행 꿀팁 등으로 구성돼 있다.
- 유심과 eSIM 목록을 분리하고 여행 일수에 맞는 상품을 찾도록 구성했다.
- 광고센터는 통합 로그인, 광고주 화면과 관리자 검수 화면을 갖췄다.
- 광고주는 캠페인 → 광고그룹 → 소재를 만들고 수정·켜기·끄기·삭제할 수 있다.
- 관리자는 광고를 승인·반려하고 광고 변경 이력을 확인할 수 있다.
- 광고그룹의 종류·국가·사용 일수가 바뀌면 승인된 소재는 노출을 중지하고 재검수 대기로 전환된다. 이름이나 입찰가만 바꾸면 재검수하지 않는다.
- 노출수·클릭수와 캠페인·그룹·소재별 성과 표시 기능이 있다. 현재 클릭 집계만으로 실제 과금에 적합하다는 뜻은 아니다.
- 관리자 인증 앱 설정 화면과 충전·환불 시 2단계 인증 확인이 준비돼 있다. 관리자 인증 앱은 아직 등록하지 않았고 관리자 업무 전체에 대한 인증 강제도 아직 꺼져 있다.
- 수동 충전, 잔액, 광고비 차감, 클릭 전액 환불의 서버 기반을 마련했다. 실제 과금과 충전은 꺼져 있으며 실제 잔액 차감은 발생하지 않는다.
- Google Play Console 계정은 만들었으나 주소 인증을 아직 마치지 못했다.

3. 아직 해야 할 일
- 부분 환불과 잘못된 충전 취소: 서버와 비공개 관리자 화면을 연결하고 가상 거래를 롤백해 중복 요청·환불액 초과·잔액 부족·2단계 인증 차단을 확인했다. 실제 인증 앱·브라우저와 동시 요청 시험이 남았다. 서버 시험은 test/finance_corrections.test.mjs에 있다.
- 관리자 인증 앱을 직접 등록하고 분실 시 복구 방법을 준비한 뒤 실제 인증을 시험한다. 관리자 업무 전체에 2단계 인증을 필수로 할지는 복구 준비 후 설정한다.
- 광고 등록·검수·중지·재검수, 여러 소재와 동시에 변경하는 상황을 실제 휴대폰과 브라우저에서 시험한다.
- Google Play Console 주소 인증 및 앱 등록을 마친다. 서명과 앱 배포 요건도 확인한다.
- Play Integrity 등 앱 검증을 실제 앱과 서버에 연결하고, 클릭 재사용·위조 방지와 과금 처리를 안전하게 연결한다. 관련 검증 코드는 일부 준비됐지만 실제 서비스에 연결되지 않았다. 정상 앱 판정만으로 사람의 유효 클릭이 보장되지는 않는다.
- 잔액 부족·일 예산·동시 클릭·중복 요청·오류·환불 및 충전 취소를 격리된 시험 환경과 실제 앱에서 검증한다.
- 개인정보처리방침, 광고 이용·충전·환불 기준, 운영자와 문의처, 기록 보존 및 분쟁 처리 방침을 정한다.
- 정식 공개 전 보안 검토, 성능 확인, 계정 복구, 광고센터 공개 범위와 스토어 심사 요건을 확인한다.

4. 운영 주의사항
- 지금은 무료 시험 상태다. 실제 광고비 청구나 고객 입금을 시작할 단계가 아니다.
- 과금은 클릭 검증, 관리자 인증, 재무 기능, 운영 정책 및 실제 환경 시험이 끝난 뒤 별도 검토한다.
- 인증 코드, 비밀번호, 서비스 비밀 키는 이 파일이나 GitHub에 기록하지 않는다.
- 세부 기술 현황: docs/BILLING_STATUS.md, docs/GROUP_TARGETING_REVIEW.md

5. 출시까지의 예상 작업과 일정

아래 2일은 Play Console 없이 진행할 수 있는 작업의 목표다. 확정 일정이나
정식 출시 보장은 아니다. 개발자 1명이 작업한다고 가정하며, 데이터베이스
변경 확인과 실제 기기 시험에서 나오는 결과에 따라 더 걸릴 수 있다.

첫째 날 목표: 부분 환불·충전 취소 기능 연결
- 이미 만든 서버 초안과 관리자 화면 초안을 함께 검토한다.
- 데이터베이스 변경은 2026-11-11에 적용됐다. 가상 거래 시험은 롤백했다.
- 격리된 환경에서 두 요청이 동시에 들어오는 경우, 같은 요청을 다시 보내는
  경우, 원래 결제액 초과, 잔액 부족, 오류 및 연결 끊김을 시험한다.
- 관리자 화면을 연결했다. 추가 검증은 시험 금액을 사용하며 실제 과금은 끈다.
- 이 단계가 끝나는 조건: 관리자 인증 후 부분 환불과 충전 취소가 기록되고,
  잔액과 내역이 맞으며 잘못된 중복 처리가 없는 것을 확인한다.

둘째 날 목표: 관리자 인증과 전체 흐름 시험
- 사용자가 관리자 센터에서 인증 앱을 직접 등록하고 분실 시 복구 방법을
  확인한다. 설정 키와 6자리 인증번호는 다른 사람에게 전달하지 않는다.
- 광고주 가입·로그인, 캠페인·광고그룹·소재 등록과 수정, 관리자 승인·반려,
  유심·eSIM 분리, 광고 켜기·끄기를 실제 화면에서 확인한다.
- 시험용 충전·차감·예산 중지·환불 흐름과 오류 상황을 확인하고 발견된
  문제를 수정한다. 실제 광고주에게 입금받거나 비용을 청구하지 않는다.
- 이 단계가 끝나는 조건: 시험 결과와 남은 문제를 기록하고, 실패한 항목은
  해결하거나 정식 출시 전 필수 작업으로 명시한다.

위 두 날은 작업 목표이며 사용자 인증 앱 등록, 데이터베이스 변경 확인,
실제 휴대폰 접근이 필요한 단계는 해당 준비가 되어야 진행할 수 있다.

Play Console 준비 후 해야 할 작업
- 주소 인증과 개발자 계정 확인을 마치고 앱을 등록한다.
- 앱 서명 및 Google Play의 앱 무결성 검증을 준비한다.
- 앱과 신뢰할 수 있는 서버를 연결해 클릭 검증과 중복·재사용 방지를 구현한다.
  현재 관련 코드 일부만 준비되어 있고 실제 클릭이나 청구에 연결되지 않았다.
- 검증된 클릭, 예산과 잔액, 무효 클릭 처리 및 환불을 실제 환경에서 시험한다.
- 개인정보처리방침, 광고 이용·충전·환불 기준, 운영자와 문의처를 마련하고
  스토어 등록 정보와 심사 요건을 확인한다.

앞서 언급한 전체 3~6주는 유료 광고 개발과 시험을 포함한 대략적인 추정이다.
실측 일정이 아니며, Play Console 주소 인증·Google 심사·정책 준비는 별도로
걸릴 수 있다. 특히 클릭 검증은 아직 실제 앱에 연결해 보지 않아 기간의
불확실성이 크다. 2일 목표를 끝냈다는 것만으로 유료 정식 출시를 뜻하지 않는다.
