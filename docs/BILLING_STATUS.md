# CPC 과금 준비 상태

실제 과금과 충전은 기본 설정에서 **꺼져 있다**. 설정을 켜거나 입금을 받기 전에 아래 작업과 검증이 모두 필요하다. 현재 무료 광고가 계속 노출된다.

구현된 서버 기반: 관리자 입금 확인 시 원장과 잔액을 같은 트랜잭션에서 기록하고 같은 요청 번호는 한 번만 처리한다. 클릭 시 서버가 해당 그룹의 입찰가를 보관한다. 신뢰할 수 있는 검증 서비스가 검증 표시를 한 클릭에 대해서만 서버 전용 차감 함수가 잔액, 일 예산, 승인·노출 상태와 중복 처리를 확인한다. 과금이 활성화된 경우 남은 잔액이나 예산이 다음 클릭 입찰가보다 적으면 조회에서 광고를 제외한다. 관리자 잔액 화면과 비용·잔액 표시도 준비되어 있지만 비활성 상태에서는 조작을 막고 비용을 표시하지 않는다.

**남은 필수 작업:**
- Play Console/Google Cloud에서 실제 앱 검증을 설정하고, 서버 전용 인증 정보로 Play Integrity 결과의 무결성·패키지·서명·nonce·재사용 방지·유효시간을 검증하는 서비스를 구현한다. 현재 검증 서비스는 없다. 클라이언트가 보낸 식별자나 `candidate`만으로 인증되었다고 판단하면 안 된다.
- 검증 서비스는 동일 클릭에 재시도해도 한 번만 처리하도록 `verified_ad_clicks` 및 서버 전용 차감 함수와 안전하게 연결한다. API 비밀키는 앱·웹 클라이언트나 Git에 넣지 않는다.
- 고객에게 입금을 받기 전에 관리자 2단계 인증, 계정 보안, 입금 고유번호 검증, 중복 정산 방지, 충전·차감 취소·환불과 감사 기록, 데이터 보존·삭제 정책을 구현하고 검증한다. 잔액 계정 삭제와 법적 기록 보존을 함께 설계한다.
- 예산 초과, 잔액 부족, 자정 경계, 동시 클릭, 광고 중지·재검수, 관리자 재시도, 결제 실패 및 네트워크 오류를 격리된 환경과 실제 앱에서 시험한다. 동시 노출 후 잔액 부족으로 청구되지 않는 클릭이 생길 수 있으며, 제공 및 정산 정책이 필요하다.
- 개인정보처리방침, 고지·분쟁 처리, 실제 사업자·문의처를 확정하고 광고주가 충전과 비용 내역을 이해할 수 있도록 검토한다. 관리자 화면의 충전 버튼은 현재 비활성이다.
- 금액 표시의 숫자 정밀도와 대규모 데이터의 성능을 점검한다. 실제 결제 금액은 서버의 정수 원장 값을 기준으로 한다.

과금 활성화는 위 조건을 충족하고 테스트한 후 별도 검토해야 한다. 현재 광고 클릭은 위조될 수 있으며 실제 청구나 잔액 차감이 일어나지 않는다.
