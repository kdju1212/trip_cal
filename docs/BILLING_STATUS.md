# CPC 과금 준비 상태

실제 과금과 충전은 기본 설정에서 **꺼져 있다**. 설정을 켜거나 입금을 받기 전에 아래 작업과 검증이 모두 필요하다. 현재 무료 광고가 계속 노출된다.

구현된 서버 기반: 관리자 입금 확인 시 원장과 잔액을 같은 트랜잭션에서 기록하고 같은 요청 번호는 한 번만 처리한다. 클릭 시 서버가 해당 그룹의 입찰가를 보관한다. 신뢰할 수 있는 검증 서비스가 검증 표시를 한 클릭에 대해서만 서버 전용 차감 함수가 잔액, 일 예산, 승인·노출 상태와 중복 처리를 확인한다. 과금이 활성화된 경우 남은 잔액이나 예산이 다음 클릭 입찰가보다 적으면 조회에서 광고를 제외한다. 관리자 잔액 화면과 비용·잔액 표시도 준비되어 있지만 비활성 상태에서는 조작을 막고 비용을 표시하지 않는다. 클릭 차감의 전액 환불은 원장에 별도 이력을 남기고 잔액과 순비용을 복원하며, 충전·환불과 타인의 금융 내역 조회에는 2단계 인증된 관리자 세션이 필요하다. 광고 변경 이력도 기록한다.

**남은 필수 작업:**
- Play Console/Google Cloud에서 실제 앱 검증을 설정하고, 서버 전용 인증 정보로 Play Integrity 결과의 무결성·패키지·서명·nonce·재사용 방지·유효시간을 검증하는 서비스를 구현한다. Google OAuth 서명·토큰 복호화 API 호출 클라이언트와 판정값의 형식·유효시간·서명 등을 검사하는 함수만 준비되어 있고, 이 코드들은 배포되거나 실제 클릭과 연결되지 않았다. 신뢰할 수 있는 서버 검증 서비스는 아직 없다. 클라이언트가 보낸 식별자나 `candidate`만으로 인증되었다고 판단하면 안 된다.
- 검증 서비스는 동일 클릭에 재시도해도 한 번만 처리하도록 `verified_ad_clicks` 및 서버 전용 차감 함수와 안전하게 연결한다. API 비밀키는 앱·웹 클라이언트나 Git에 넣지 않는다.
- 고객에게 입금을 받기 전에 관리자가 인증 앱을 직접 등록해 실제 2단계 인증과 계정 복구를 시험한다. 광고 검수 등 다른 관리자 작업까지 보호하는 2단계 인증 강제 설정을 마련했지만, 인증 앱 등록 전에는 켤 수 없고 기본적으로 꺼져 있다. 관리자 센터에서 등록 후 인증된 세션으로 명시적으로 켜야 하며, 다른 관리자도 모두 2단계 인증이 필요해진다. 입금 고유번호 검증, 부분 환불·충전 취소, 분쟁 처리, 감사 기록 보존·삭제 정책을 완성한다. 현재 전액 클릭 환불과 핵심 금융 작업의 서버 측 2단계 인증 조건만 구현되었다. 잔액 계정 삭제와 법적 기록 보존을 함께 설계한다.
- 예산 초과, 잔액 부족, 자정 경계, 동시 클릭, 광고 중지·재검수, 관리자 재시도, 결제 실패 및 네트워크 오류를 격리된 환경과 실제 앱에서 시험한다. 동시 노출 후 잔액 부족으로 청구되지 않는 클릭이 생길 수 있으며, 제공 및 정산 정책이 필요하다.
- 개인정보처리방침, 고지·분쟁 처리, 실제 사업자·문의처를 확정하고 광고주가 충전과 비용 내역을 이해할 수 있도록 검토한다. 관리자 화면의 충전 버튼은 현재 비활성이다.
- 정수 금액을 문자열과 BigInt로 표시하도록 했지만, 많은 항목을 여러 요청으로 조회할 때 동시 변경에 따른 집계 불일치와 대규모 데이터 성능을 점검한다. 실제 결제 금액은 서버의 정수 원장 값을 기준으로 한다.

과금 활성화는 위 조건을 충족하고 테스트한 후 별도 검토해야 한다. 현재 광고 클릭은 위조될 수 있으며 실제 청구나 잔액 차감이 일어나지 않는다.

테스트용 판단 함수는 Google이 서버에 직접 반환한 검증 응답에만 사용해야 한다. 앱에서 보낸 JSON을 그대로 신뢰하거나 검증 표시를 하면 안 된다. 서버가 발급한 1회용 요청과 이벤트를 바인딩하고, 진위 검증·재사용 방지·과금 처리를 원자적으로 연결해야 한다. Google Play의 정상 앱 판정만으로 실제 사람의 진짜 클릭이 보장되는 것은 아니다.
