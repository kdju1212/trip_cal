# 유심·eSIM 업체 광고 설정

앱은 Supabase PostgREST에서 광고 상품을 읽습니다. 프로젝트 생성 및 상품 등록은 별도로 필요하며, 연결되지 않으면 광고 없이 기존 쇼핑 검색을 보여줍니다. 계정 생성, 프로젝트 생성, SQL 적용과 결제 설정은 자동으로 수행되지 않습니다.

## 설정

1. Supabase 프로젝트를 만들고 `supabase/migrations/202611080001_sim_ads.sql`을 SQL Editor에서 실행합니다. 실행 전 SQL을 검토하세요.
2. 프로젝트 URL과 **공개용** anon 또는 publishable 키를 준비합니다. `service_role`, secret 키나 DB 비밀번호를 앱, Git, 빌드 인자에 넣지 마세요. 클라이언트 키는 앱에서 추출할 수 있습니다.
3. GitHub 저장소의 Actions variables `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 설정하거나 다음처럼 빌드합니다.

   ```sh
   flutter build apk --release --no-shrink --split-per-abi \
     --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
     --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_KEY
   ```

4. 대시보드 Table Editor에서 `sim_ads`에 광고주명, 상품명, `sim_type` (`sim` 또는 `esim`), ISO 국가 코드(예: `JP`), 실제 이용 일수, 가격(원), HTTPS 구매 링크를 등록합니다. 이미지 URL은 HTTPS만 사용합니다. 공개 준비가 완료되면 `is_active`를 true로 설정합니다. 시작·종료 시간을 선택적으로 설정할 수 있습니다. 현재 시점에 활성화된 상품만 공개됩니다.
5. 앱에서는 여행 국가·종류·일수와 정확히 일치하는 상품을 가져옵니다. 여행 날짜가 없으면 해당 국가와 종류의 모든 일수를 표시합니다. 상품을 누르면 외부 구매 링크가 열립니다. 광고주가 웹 화면에서 제출한 광고는 관리자가 Supabase 대시보드에서 검토하고 별도로 공개합니다.

## 운영 시 확인

- 상품 가격과 조건, 링크의 유효성을 관리자가 확인하고 갱신해야 합니다. 가격은 등록값이며 실시간 가격이 아닙니다.
- RLS 정책은 활성화된 행의 지정된 열만 공개합니다. 익명 사용자는 등록·수정·삭제를 할 수 없습니다. 광고주 연락처나 내부 계약정보 같은 비공개 정보는 이 공개 테이블에 넣지 마세요.
- 이미지가 외부 URL이면 해당 서버가 사용자 IP를 받을 수 있습니다. Supabase 접속과 외부 이미지·판매처 이동에 관한 내용을 실제 운영 환경에 맞춰 개인정보처리방침에 반영하세요.
- 앱은 광고 항목에 `광고`를 표시하며 제휴 링크 사용 여부와 사업자 표시, 광고 표시에 필요한 사항은 실제 계약과 운영 환경에 맞게 정리하세요.

## 광고주 계정과 미리보기

`advertiser/`는 별도로 정적 호스팅하는 광고주 화면입니다. 로컬 화면 미리보기는 해당 디렉터리를 HTTP로 제공한 뒤 `index.html?preview=1`에서 확인할 수 있으며, 이 모드에서는 등록하지 않습니다. 앱이 아닌 별도 웹 화면입니다.

1. 기존 광고 SQL을 먼저 적용하고 `supabase/migrations/202611080002_advertiser_drafts.sql`을 추가 적용합니다. `ad-draft-images`는 비공개 버킷이고 광고주가 자신의 폴더에만 업로드할 수 있습니다. 로그인한 광고주는 자신의 검토 요청만 볼 수 있습니다.
2. Supabase Auth에서 이메일 가입과 이메일 확인을 설정하고, 호스팅할 광고주 웹사이트 주소를 Auth Site URL 및 Redirect URL에 등록합니다. 공개 가입 정책, 메일 발송량, 이용약관·개인정보 안내를 운영 전에 확인하세요.
3. `advertiser/config.js`에 프로젝트 URL과 **공개용** anon/publishable 키를 설정하고 정적 호스팅에 `advertiser/` 디렉터리를 배포합니다. 비밀 키는 절대 넣지 마세요. 비어 있으면 브라우저에서 공개 연결 정보를 입력하는 화면이 표시됩니다.
4. 광고주는 회원가입·로그인 후 이미지, 제목, 한 줄 설명과 국가·종류·일수·가격·HTTPS 구매 링크를 입력하고 화면에서 미리 본 뒤 검토 요청을 보냅니다. 이 요청은 `advertiser_drafts`에만 저장되며 앱에 자동 노출되지 않습니다.
5. 운영자는 대시보드에서 내용을 검토하고 Storage의 비공개 `ad-draft-images`에서 이미지를 확인합니다. 승인 시 이미지를 공개 이미지 저장소에 올려 HTTPS URL을 얻고 `sim_ads`에 검토한 값을 직접 복사해 `is_active`를 true로 설정합니다. 광고주 수정은 이미 공개한 상품을 자동으로 변경하지 않습니다. 거절 통보·승인 상태 변경·자동 게재는 구현되어 있지 않으므로 운영자가 별도 안내합니다.

광고 이미지는 업로드 전에 JPG/PNG/WEBP 및 3MB 제한을 확인합니다. 등록 취소·삭제, 광고주별 수정·운영자 승인 화면, 계정 복구, 업체 인증, 광고 결제·조회수 통계 및 웹사이트 배포는 아직 구현되지 않았습니다. 로그인 세션은 페이지를 닫거나 새로 고치면 다시 로그인해야 합니다. 실제 사용 전 계정 격리, 스토리지 접근 정책과 전체 등록·검토 과정을 연결된 Supabase 프로젝트에서 확인하세요.
